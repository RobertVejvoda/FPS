# Sponsor &amp; Evaluator Deck

A slide outline for a pilot go/no-go conversation. One slide per section; each carries a **Source:** link. Presenter view of the [Sponsor &amp; Evaluator Tour](../sponsor-evaluator).

---

## 1 — FairSpot in one line

- Fair, explainable access to scarce shared capacity.
- Replaces "who emailed the operator first" with a transparent booking and **Draw** process.
- Parking first; the same model covers seats, courts, desks, lockers, chargers.

*Source: [Product Overview](../../Home)*

---

## 2 — Why it matters

- **Fair access:** explicit, auditable rules; access improves over time.
- **Lower operational load:** intake, Draw, notifications, and audit are automated.
- **Trust:** rules, notifications, audit, GDPR erasure, and tenant isolation are explicit, not implicit habits.

*Source: [Sponsor &amp; Evaluator Tour → The value in one minute](../sponsor-evaluator)*

---

## 3 — The proof path

- One end-to-end loop: request → obligations honoured → fair Draw → notify → act → evidence.
- Company-car obligations are honoured before the fair Draw and can't be self-assigned.
- Walk it live in the Green Logistics showcase.

*Source: [Green Logistics Walkthrough](../green-logistics-walkthrough)*

---

## 4 — What's ready today

- Booking/Draw lifecycle, notifications, audit, reporting, configuration.
- Mobile employee journey + web employee/HR/admin surfaces.
- Durable persistence and a containerised NAS/Cloudflare hosting path.

*Source: [Client Evaluation Pack → One-Page Summary](../../client-evaluation-pack)*

---

## 5 — Rollout posture

- Local → NAS/Cloudflare (Release 1 evaluation) → DigitalOcean demo → **client-owned production**.
- FairSpot provides architecture, deployment guidance, and evidence; managed production is not promised until agreed.
- Release 1 is synthetic/demo only — not for real customer data unless explicitly agreed.

*Source: [Client Evaluation Pack → Deployment &amp; Operations](../../client-evaluation-pack#deployment-and-operations-summary)*

---

## 6 — Boundaries to know

- SSO-first; FairSpot does not store customer passwords or replace the IdP.
- Billing is not implemented — commercialisation is a later decision.
- Cost is discussed profile-based, not as numeric commitments.
- Hosted-operator internals are a separate commercial platform plane (private `fairspot-platform`).

*Source: [Sponsor &amp; Evaluator Tour → Boundaries](../sponsor-evaluator)*

---

## 7 — Decide the next step

- The authoritative, current status is the Roadmap and Release 1 Scope.
- A pilot needs: hosted demo evidence, mobile polish, admin surfaces where needed, observability + backup/restore evidence, and a production-handoff model.

*Source: [Roadmap → Release 1 Scope](../../roadmap#release-1-scope)*
